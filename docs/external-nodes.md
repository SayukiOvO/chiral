# 外部节点

别人提供的节点：机场订阅，或朋友直接发来的一条链接。这些机器不是你的，装不了 Agent，所以面板对它们做不了它对自有节点做的任何事。

**先说清楚能力边界**，这是「对方给你一条链接」这件事本身的性质，不是以后能补的缺口：

- **所有订阅者共用同一份凭证**——对方只给了你一条，没有按用户隔离。
- **没有流量统计**——流量在对方那边计，面板看不到。
- **停用某个用户不会让他连不上**——凭证不是面板发的，收不回来。
- 只出现在 Clash 类订阅里（`clash` / `stash`）。xray-json 与分享链接不含它们。

## 来源

两种：

- **订阅链接**——每天自动更新一次。
- **直接粘贴**——不自动更新，适合朋友发来的单条链接。

格式**自动识别**，因为机场不会告诉你它给的是哪种，同一家换个套餐都可能变：

| | |
|---|---|
| Clash YAML | 取 `proxies:` 段 |
| 分享链接列表 | 每行一条 |
| 整体 base64 的链接列表 | v2rayN 风格订阅的常见形态 |

链接支持 `vless://`、`vmess://`、`trojan://`、`ss://`，含 REALITY、ws、gRPC 等传输参数。

**解析不了的单条会被跳过，不牵连整个来源**——机场经常带上面板没见过的协议类型，其余的照样能用。

## 链式代理

每个外部节点可以单独指定「经由本机队的哪台节点」。这样对方看到的是**你的节点**，而不是订阅者。

Clash 侧落成 `dialer-proxy`。有一处不显然：**`dialer-proxy` 必须指向同一份文档里存在的代理**，否则客户端拒绝整份配置。所以当某个订阅者拿不到那台前置节点时，该外部节点会被**整个略去**，而不是降级成直连——降级会把这个设置存在的意义悄悄取消掉，而订阅者不会知道。

## 刷新与设置保留

刷新会重新解析并替换节点列表，但**每个节点上的设置（链式、启用）会带过来**：先按名字匹配，名字变了再按 `server:port` 兜底。

机场经常把剩余流量和到期日写进节点名（`🇭🇰 香港 01 | 剩余 82%`），只按名字匹配的话，对方每改一次标签你的链式配置就断一次——而且没人会想到去复查。

## 与规则的关系

外部节点像自有节点一样出现在 `proxies` 里，因此会被分流规则的策略组正常选中。规则本身不区分节点来源。

## 边界

- 外部节点对**所有**订阅者可见，没有按用户指派。
- 面板不校验对方节点是否可用——没有 Agent，无从探测。节点显示为可选，通不通要客户端自己测。
- 来源可整体停用，单个节点也可单独停用。
