# 用户组：把「谁能用哪个节点」决定一次

## 动机

在此之前，访问权限逐人存储：接入配置是授予表（`user_profiles`），节点 / 中转线路 / 外部节点是拒绝表（`user_node_denies` 等），新建节点时为**当时所有订阅者**写入拒绝行，新建用户时同理。默认关闭是对的，代价是每加一台节点就要重复 N 次同一个决定——而重复 N 次的决定，最后总会由一个循环来做，不是由人来做。这个功能要防的正是这个形状。

## 归属是单一的

一位订阅者至多属于一个组，`users.group_id` 为空即完全等同于没有组时的行为。

多对多曾是显而易见的备选，但它**无法表达拒绝**：权限在多个组之间取并集时，只要有一个组允许某节点，其余组的拒绝就全部失效——而本面板的节点控制本身就是拒绝表。这与「空 `user` 列表匹配所有人」是同一类陷阱：一个看起来更灵活的设计，把一整张安全表悄悄变成了装饰。

## 判定次序：个人 > 组 > 默认

每个对象三态，无行即继承。为此每个维度都需要两张个人表：

| 维度 | 组 | 个人（授予） | 个人（拒绝） |
|---|---|---|---|
| 接入配置 | `group_profiles` | `user_profiles` | `user_profile_denies` |
| 节点 | `group_node_denies` | `user_node_allows` | `user_node_denies` |
| 中转线路 | `group_relay_denies` | `user_relay_allows` | `user_relay_denies` |
| 外部节点 | `group_external_denies` | `user_external_allows` | `user_external_denies` |
| 分流规则 | `subscriber_groups.ruleset_id` | `users.ruleset_id` | `users.ruleset_none` |

解析发生在 store 内部：`UserProfileIDs`、`ProfileUserIDs`、`UserNodeDenies` 等**函数名不变、返回值改为解析后的结果**。订阅装配、凭证铸造与控制台问的是同一个问题，绝不能各自给出不同答案；`ProfileUserIDs` 尤其关键，它决定节点上存在哪些凭证，漏掉组授予就会出现「订阅里有这个节点、连上去却被拒」。

`ruleset_none` 是必需的第三态：空的 `ruleset_id` 现在意味着「继承」，若不另设标记，组内成员就无法表达「我不要任何分流规则」。

## 三处默认必须关闭

1. **新建组**：对当时存在的每个节点 / 线路 / 外部节点写入拒绝行。运维接下来的动作是「把人放进去」，不是「审计这个组已经隐含了什么」。
2. **新建节点 / 线路 / 外部节点**：除给每位订阅者写拒绝行外，**也给每个组写一行**。少了这一半，机队买的下一台机器会在绑定的瞬间到达整组成员。
3. **新建订阅者**：维持原状（对已存在的节点全部拒绝）。

## 加入与离开是不对称的，两者都不会凭空增加权限

**加入组会清空该成员的个人行。** 今天每个 (订阅者, 节点) 对都有物化的拒绝行，若保留，成员将被自己的例外完整覆盖，组永远不会生效。这是该功能唯一的破坏性操作，因此控制台在发起请求前明确告知将被清除的内容。

**离开组（或删除组）会把组当时的决定写进成员自己的行。** 反过来做的话，一个成员在离开时会突然「不被任何东西拒绝」——也就是拿到整个机队。删除组是解散它，不是公布它。

## 整集编辑器只写差异

控制台保存的是终态（「这些节点他不能用」），而组内成员的终态大部分本来就是组说的。若逐个对象照写，第一次保存就会把组埋在一整套例外之下，此后组不再决定任何事，而且没有人碰过它。因此 `SetUserNodeAccess` 与从对象一侧编辑的 `SetNodeRelayAccess` / `SetExternalProxyAccess` 都改为**与组的答案比对后只写差异**：一致则不留行，不一致才写一条例外。

## 受限目的地

`restricted_destination_group_allows` 允许按组放行，与按人放行**取并集**。组在此只是成员的简写，在装配时展开（`blocksFor`），因此成员变动无需回头修改目的地。方向不变：这仍是全面板唯一的白名单，未指定任何用户与组的目的地对所有人关闭；**全员获准时必须不发规则**，而不是发一条空 `user` 列表的规则。

## 验过什么

- `store`：新建组不持有任何东西、之后新建的节点同样被拒绝；组为成员决定授予与拒绝；加入清空个人行；个人例外双向覆盖组、清除后交还给组；与组一致的保存不产生任何行；离开与删除保留组当时的决定；分流规则三态解析。以上七项均做过变异验证。
- `profile`：受限目的地按组放行，成员不被拦截；全员获准时规则消失。
- `api`：组授予到达成员（含 `entitled` 与 `from_group` 标记）；经 API 加入组会清空个人行并删除失效凭证；分流规则继承与「单独排除」。
