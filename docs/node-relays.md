# 中转线路：自有节点经自有节点

## 它是什么

一条线路（`node_relays` 一行）= **入口节点 + 出口节点 + 出口的一个接入配置 + 一个名字**。订阅者连入口，流量从出口出去。

机制和[外部节点的服务端中继](external-nodes.md#前置中继经自有节点与链式经外部节点)一模一样——出口成为入口上的一条 outbound，一条按 email 匹配的 routing 规则把该走这条线的凭证送过去——只是两端都是自己的机器。

**但目的是反的。** 外部中继是为了**藏落地**：对方机场的地址不能让订阅者看见。这里两端都是我们的，订阅者本来就能看见出口（它自己就是一条线），藏无可藏。中转要解决的是**够不到**：订阅者到远端出口的直连很差，但到附近的入口很好，而入口到出口很好。

所以它是**第三条线**，不是任何一端的替代品。入口、出口、这条中转，订阅里同时存在三条，各有各的名字。

## 那份「机器凭证」

入口拨出口用的是**一条线路一份**凭证，不是一人一份——Xray 的 outbound 是静态的，它出示什么不可能取决于正在承载谁的连接。

这份凭证不属于任何自然人，所以**不进 `credentials` 表**，而是存在 `node_relays.secret`（AES-GCM 密封，和其它密钥一样）。理由不是洁癖：

- `credentials` 是按 `user_id` 建的，没有 user 可填；
- 计费必须**只发生一次**，在订阅者认证的那个入口上。如果这条线自己的字节也落到某个凭证上，同一个 GB 会被计两遍——一遍算在人头上，一遍算在机器头上。

出口那边把它当成**普通 client** 收下（`relay.<线路 id>@<接入配置 id>.<出口节点 id>`）。`AddCredentialTraffic` 认不出这个 email，直接跳过——对这条线自己的字节而言，这正是对的行为。

它也是**面板里唯一不给人看的凭证**：两端都是我们的机器，两端都从下发的 config 里拿到它，没有任何人需要读或抄它，所以控制台的 API 不返回它。

## 入口拿什么去拨号

**出口那个接入配置的 `xray-json` 客户端模板**，用这份机器凭证渲染，tag 钉成 `relay-<线路 id>`。

这一条是有意选的。另一条路是「从服务端 inbound 反推客户端 outbound」——要重新推 REALITY 公钥、镜像每一个传输参数，还要跟着协议一起长，而且是**第二份**必须和第一份保持同步的实现。复用模板意味着入口拨出口的方式和订阅者客户端拨它的方式**是同一件事**，不可能漂移。（探活用的 `probe_outbound` 也是同一个理由、同一份模板，见 [xray-upgrade.md](xray-upgrade.md)。）

代价是**没有 `xray-json` 模板就没有线路**。这不会被默默吞掉：控制台那一行会红字说明，`Apply` 会带着原因拒绝，两条路径都点名是哪个接入配置缺什么。同理，**出口若不再绑定那个接入配置**，线路也会红字标出——两个原因都是运维在别的页面上做的事，而不标出来的症状是「订阅里多了一条永远连不上的代理」。

## 权限

线路有**自己的**一张拒绝表（`user_relay_denies`），既不复用入口的也不复用出口的。因为这是第三个问题：「能直连东京吗」「能用东京那台机器吗」「能经香港去东京吗」是三个独立的答案，而跑中转的理由通常正是第一个为否、第三个该为是。

- **新建的线路默认谁都不能用**，和新节点、新外部来源一致：加一条路和决定它给谁，是两件事。
- **入口被拒绝，经它的线路一起消失。** 一条经某台机器的线路 = 那台机器的地址 + 一份能用的凭证；带着线路却说「拒绝了那个节点」等于把刚收回的东西原样递出去。
- 一个没有任何人有权使用的出口**只给 outbound、不给规则**——空的 `user` 列表匹配的是所有用户而不是没有用户，「谁都不能用」和「谁都能用」在输出里只差一个字符。

## 计费

`credentials.exit_relay_id` 指向线路，倍率取线路的（见 [user-management.md §流量倍率](user-management.md#流量倍率)）。计的是**入口那一次**，因为那是订阅者认证的地方；出口上那条线自己的计数器只是「这条线搬了多少」，不进任何人的配额。

## 边界

- **一跳。** A→B 的凭证到了 B 之后没有任何规则命中，走 B 的默认 outbound 出去。要 A→B→C 得让 B 上那份机器凭证再被一条规则接住，现在不做。
- **入口不能是出口自己**（写入时拒绝）。
- 一对节点 × 一个接入配置只能有一条线（`UNIQUE`）——两条就是两条一模一样的代理。
- 删除任一端节点或那个接入配置，线路跟着级联删除；订阅者那份 `exit_relay_id` 凭证也跟着走。

## 验过什么

`core/internal/profile/relay_e2e_test.go` 起**两个真的 xray 内核**：入口的默认 outbound 是 `blackhole`，所以到得了目的地就只可能是从出口出去的。反向的对照同样重要——**同一个人、同一个 inbound、只换一份凭证**（直连的那份）必须打不通。少了这半边，「通了」也可能是入口把所有人都往线路上送。

拿掉规则里的 `user` 字段（模拟「规则匹配得太宽」这个 bug）之后，对照那一半确实会失败；改回来就过。
