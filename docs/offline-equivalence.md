# 离线配置与订阅等价性核验

`core/cmd/equivalence` 是独立核验工具，不是 Core 的启动模式。它不会启动 HTTP/gRPC、
连接 Agent、执行迁移或修复、刷新外部订阅和规则源，也不会补发凭证或重置订阅 token。
此工具不会接管 3x-ui；通过离线比较不能证明节点运行、计费、在线观测或更新已通过验收。

## 输入与安全要求

输入必须是**已经完成的 SQLite `.backup` 单文件副本**，不得指向运行中的数据库。
工具不能仅凭文件格式证明操作者使用了 `.backup`；备份来源和一致性仍须由操作者记录。
禁止使用正在写入的副本或只复制 WAL 模式下的主文件。工具拒绝符号链接及存在
`-wal`、`-shm`、`-journal` 的输入，不负责删除这些文件。

打开方式固定为只读、`immutable`、`query_only`，不运行迁移。迁移名称集合必须与构建
完全匹配，并通过 SQLite 完整性与外键检查；旧版或未来 schema 必须由相应版本的核验器
读取，不能为获得通过而改写迁移记录。开始及结束时比较输入身份和 SHA-256，拒绝中途
变化；这不是针对恶意并发修改者的文件系统隔离。

需要与该副本一致的 `CHIRAL_SECRET_KEY`、原公共 URL，以及显式指定的同一核验时间。
密钥只从环境读取，不接受命令行参数、不输出密钥。未加密的合成库可以不设密钥。
没有可恢复 token 的旧用户明确标为不完整，不能重新生成 token 后声称订阅不变。

输出包含解密后的节点配置、订阅正文及其中的真实凭证。工具只创建新的 `0700` 目录和
`0600` 文件，拒绝覆盖。**禁止提交到 Git、上传 PR 或粘贴到聊天。** 终端仅输出计数和
布尔结果；错误采用固定诊断，不回显模板、凭证、数据库错误或命令行输入。

## 比较范围

- 每个用户 × `xray-json`、`clash`、`vless-uri`、`stash`：正文原字节、成功响应头及订阅 token
  的 SHA-256 身份；正文未嵌入 token 时，也不能漏掉导致原订阅链接失效的变化。
  停用、过期和超额用户仍按现有订阅语义导出列表；状态头与节点有效凭证筛选使用同一固定时间。
- 每个节点：最新可下发的存储配置原字节，以及当前模板重新组装的配置原字节，分别比较。
  不将“历史内容等于自身”当作新渲染等价；不执行 `xray -test` 或下发。
- 用户所选规则集引用的缓存规则正文：以实际 provider YAML 渲染比较，缺失缓存单独失败。
  外部节点继续由原订阅渲染路径使用缓存生成，不联网刷新。

订阅继续使用现有授权和隐藏模板规则，不新增授权。缺失应有凭证、无法解密 token、空订阅、
渲染跳过、规则或外部依赖渲染错误均标为不完整。当前完整性判定保守要求每位用户的四种
客户端均有有效内容；有意未提供某格式或无任何授权的用户也不能得到全格式完整 PASS，
但仍保存其证据，不自动删除用户或扩大权限来满足核验。

不覆盖全部配置历史、升级探针凭证、门户界面或生产网络。普通配置读取可能省略无法解密
的探针，因此工具明确不把该字段算入已验证范围。成功响应头由线上 handler 与核验器共用
生成函数；失败订阅不伪造 HTTP 200，也不将两个相同的空结果判为通过。

## 使用方式

在仓库根目录构建：

```bash
go build -o bin/chiral-equivalence ./core/cmd/equivalence
```

以下路径均为示例，必须替换为已准备好的私有备份和**不存在**的输出目录。此操作不会获取
生产备份；访问生产、备份传输和实际迁移必须另按授权执行。

```bash
bin/chiral-equivalence export \
  --db /private/verification/before.db \
  --out /private/verification/before-export \
  --public-url https://panel.example.invalid \
  --at 2026-09-29T00:00:00Z \
  --revision 'VERIFIED_BASELINE_BUILD_SHA'

bin/chiral-equivalence compare \
  --before /private/verification/before-export/bundle.json \
  --after /private/verification/after-export/bundle.json
```

基线与候选必须分别由对应构建导出，以同一固定时间、URL、密钥和同源缓存为输入；候选副本
的迁移应使用真实目标迁移路径单独预演，然后封存再核验。`--revision` 是操作者记录的构建
来源，工具不替操作者证明二进制来源。旧构建没有本工具时，不能用新版渲染两次替代旧版
对照；需先准备等价的基线导出入口并验证其不改变基线行为。

比较时允许数据库散列和构建版本不同，正文、头、记录清单及核验参数必须相同。不进行
JSON/YAML 格式化或语义归一化来掩盖字节差异。

退出状态：`0` 表示导出完整或比较通过；`2` 表示证据已保存但不完整，或比较未通过；
`1` 表示输入、读写或执行失败。比较输出将 `equal`、`complete`、`passed` 分开；
只有 `passed=true` 且进程退出为 `0` 才通过该离线检查。两份相同的不完整证据不能通过。
