# 分流规则

Clash 类客户端的订阅此前只有 `proxies` 和两个策略组，没有任何 `rules`，于是客户端把**所有**流量都送进代理——订阅者的银行、局域网打印机、以及本来就该直连的国内站点。分流规则是让订阅从「连得上」变成「能用」的那一步。

规则集**按用户**指派：运维在用户页设，订阅者也可在门户自己改。同一个人可能要全代理，另一个人要国内直连，这是偏好而不是策略。

## 来源

格式是 subconverter 的远程配置（ACL4SSR 各档预设就是用它写的），两条指令承载全部内容：

```ini
ruleset=<策略组>,<规则列表 URL>     ; 一份规则列表，命中后走该组
ruleset=<策略组>,[]<规则>          ; 单条内联规则，如 []GEOIP,CN、[]FINAL
custom_proxy_group=<名>`<类型>`<成员>`<成员>...
```

成员写作 `[]名字` 表示字面量（另一个组、`DIRECT`、`REJECT`），否则是**按节点名匹配的正则**——地区分组（香港/日本/美国）就是这么来的。`url-test` / `fallback` / `load-balance` 三类组的末尾还带 `` `<测速URL>`<间隔>,<超时>,<容差> ``。

内置 33 套 ACL4SSR 预设，也可填任意 `.ini` 地址。两者在库里是同一张表的同一组列，切换只是改一个字段。

### 解析上的两处不显然

**`[]GEOIP,CN` 是一条规则，不是「组 `[]GEOIP` + 规则 `CN`」。** 按逗号全切会切出一个格式合法、语义荒谬的配置：客户端照单全收，然后什么都不按预设的意图路由。

**非 Online 档的预设引用的是相对路径**（`rules/ACL4SSR/Clash/BanAD.list`），那是 subconverter 安装目录里自带的仓库副本。原样使用的话规则列表根本取不到，而客户端只会报「规则集为空」，不会报错。这些路径会被映射回它们镜像的那个仓库。

## 渲染上的一处不显然

**Clash 拒绝加载含空策略组的配置**——是拒绝，不是降级。而所有流行预设都带地区分组，所以只要机队在某个地区没有节点，整份订阅就废了。

空组会被丢弃，**同时丢弃其他组对它的引用、以及指向它的规则**——后两者最容易漏：一个成员指向已不存在的组，失败方式和空组一模一样。丢弃还会级联：地区组没了可能让引用它们的选择组也空掉。

## 分发

规则列表由面板下发，路径 `/sub/{token}/rules/{name}.yaml`，客户端配置里以 `rule-providers` 引用。

这样订阅正文约 5 KB，而不是把几十万条规则内联进去（Online 档约 160 KB，Full 档约 600 KB，且每次更新都重传）。上游改了规则，订阅者不需要重新导入任何东西。

**抓取永远不在订阅路径上。** 拉订阅的人往往正处在这套软件要帮他绕开的网络里——一个会去 GitHub 取东西的渲染就是一个会卡住的渲染。规则来源由后台按天刷新，渲染只读库里那份。

抓取失败**保留上一份**并把原因记在规则集上：上游不可达时应该降级成「昨天的规则」，而不是「没有规则」。

## 环境变量

| 变量 | 说明 |
|---|---|
| `CHIRAL_PUBLIC_URL` | **必需**。`rule-providers` 的地址由它拼出；留空则订阅完全不带分流规则，因为相对路径客户端解析不了 |
| `CHIRAL_GITHUB_TOKEN` | 可选。仅用于 `api.github.com`；规则列表走 `raw.githubusercontent.com`，匿名即可 |

## 边界

- 只影响 Clash 类客户端（`clash` / `mihomo` / `stash`）。xray-json 与分享链接不含路由规则，那是客户端自己的事。
- 规则集不进节点 config，只在订阅里，所以改动不需要下发节点，订阅者下次刷新即生效。
- 内置预设的来源地址不可改。要改就新建一个自定义规则集——否则一个规则集会顶着预设的名字去取别的东西。
