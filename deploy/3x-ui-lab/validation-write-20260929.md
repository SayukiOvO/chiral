## 源码解释与推断边界

只读核对官方提交 `7ef22f94c950ff09f0870e2295fa65ad5968742c`：

- `internal/xray/api.go` 的 `GetTraffic` 在统计映射为空时仅建立首轮基线，不将既有字节
  返回给数据库累加逻辑。这与本次“冷请求为零、后续请求正常”的实测一致；延长读取等待
  不会补回已经被基线排除的字节。Chiral 的持久化 ACK 只能保护收到的增量，不能恢复这些字节。
- `internal/web/service/xray.go` 的 `GetXrayConfig` 根据全局 client 模型重建受管入站的
  client 列表，未写入 `level`。本次证明该受管 client API 路径不保真，**不等于已经排除
  所有其他官方模板 API 组合**；替代路径仍须独立证明热更新、计费及配置等价性。
- 上游保留第零条 API 路由。早期测试把新增规则置于它之前，读回时顺序被归一化；现已修正
  测试夹具，在确认原 API 规则存在后将自有测试规则插在其后，保留原业务规则相对顺序，
  不放宽完整回读断言。
