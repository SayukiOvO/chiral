# 官方 HTTP 数据探测与恢复验证（2026-09-29）

## 结论与边界

官方未修改的 3x-ui `testOutbound` 接口已通过隔离验收；使用该 HTTP 探测器的候选更新
恢复协调器也通过三个故障场景。此结果补齐“恢复后能否通过真实代理路径取得 HTTP 响应”
的证据，**不代表真实内核下载、配置事务、计费、在线快照或整体迁移已通过**。

全程未访问 Turin，没有使用生产配置、凭证或数据。仅在本机 Docker 创建新的空实例，
没有外部网络、宿主机端口和生产挂载，没有修改 3x-ui。每轮三个容器结束后停止并保留。

## 可复现输入

- 运行器：`write_contract.py --suite http-probe`。
- 官方镜像：`ghcr.io/mhsanaei/3x-ui@sha256:e0f90c10902e0e74f947d5a9efe017b273804477430233bbfc4918542ffe366c`。
- Linux/amd64 镜像：`sha256:be0af3a71e948bab24852b5dc571fd9835834847f086a84b1c4eb5932dd0fe50`。
- 源码契约依据：官方 v3.8.5，提交 `7ef22f94c950ff09f0870e2295fa65ad5968742c`。
- 精确测试：`TestLive3XUIHTTPProbeContract`；测试程序不启动 Xray 客户端，不调用其管理 API。

上游要求测试目标为公开 HTTP(S) 地址。实验使用字面 IP 作为逻辑目标，不执行 DNS；仅
本轮专用 VLESS 入站能路由到专用 freedom 出站，再重定向到同命名空间的回环 HTTP 源站。
该出站只允许本轮源站的精确回环地址及端口，其他流量拒绝。接口检查确认只有 loopback
处于活动状态；配合 `network=none`，逻辑公网地址不会产生公网访问。此方法只适用于
隔离夹具，不能用来证明实际公网连接或业务响应正文完整性。

## 两轮结果

首轮目录 `/private/tmp/chiral-http-probe-20260929-01`：四个探测子项 PASS，4.72 秒，
测试、Docker 执行、运行器退出码均为 0，无 SKIP。随后复核发现错误凭证的判定只检查
`ContractError`，不能排除请求前的契约检查错误；故其负向证据不足，不以此轮单独验收。

第二轮使用新实例及加强后的测试，目录 `/private/tmp/chiral-http-probe-20260929-02`：
整体 PASS，31.79 秒，测试、Docker 执行、运行器退出码均为 0，无 SKIP。

| 检查 | 官方实测证据 |
| --- | --- |
| HTTP 200、204 | Chiral 返回匹配状态，每次实际命中源站一次 |
| 错误 UUID | 官方固定 POST 明确返回外层成功、匹配 tag、`real` 模式、内层失败；源站命中不增加，Chiral 拒绝，前后有效凭证成功 |
| HTTP 500 | 官方仍返回内层成功及 500；Chiral 拒绝，源站命中确认请求确已穿过代理 |
| 全部探测后 | 实例和运行版本未变化，完整模板和最终配置没有漂移 |

候选更新恢复使用同一个真实 HTTP 探测器，但**版本目录和安装返回由测试传输层注入**，
所有安装路径均被拦截，不发送真实下载请求。停止、重启、状态及数据探测调用官方接口：

| 安装故障场景 | 注入的安装请求数 | 官方恢复重启数 | 保留结果 |
| --- | ---: | ---: | --- |
| 明确失败，进程已停止 | 1 | 1 | 安装 failed，服务 reachable |
| 恢复成功但丢失恢复回应 | 1 | 1 | 安装 failed，恢复结果 unknown，服务 reachable |
| 安装回应丢失，服务仍运行 | 1 | 0 | 安装 unknown，服务 reachable，更新限制仍保留 |

三个场景均验证同 ID 重放、关闭并重新打开私有操作记录以及 `Reconcile`，没有重复派发
安装或恢复。最后再次通过官方 HTTP 发起新代理请求并确认源站命中。安装未知场景不模拟
后台真实下载，不能据此推导真实安装任务已终止；它只证明不重复派发与状态分离。
