# node — 节点会话与下发

Agent 侧的 gRPC 服务（service.go）与在线会话表（manager.go）。`Register` 用一次性 join token 换长期凭证（同一次 DB 更新里作废 token）；`Channel` 双向流上行承载 Hello / 心跳 / ConfigAck / 事件 / 流量 / 在线上报，下行承载 ConfigPush、UserOp、Command、OnlinePolicy。

## 关键决策

- **在线 = 有一条活着的会话，且最近活动在心跳超时内。** `IsOnline` 与 API 的节点列表用同一个判断，告警和界面不会各说各话。一个节点只保留一条会话，新流接入就关掉旧的。
- **重连自动对账 config**：连上时补推「最新的未失败版本」，心跳里带的 applied version 与之不符也补推，无需运维介入。同一版本 30 秒内不重复推，免得慢 Agent 被灌；被 `xray -test` 判失败的版本不会补推。推送失败不算失败——版本照存，下次心跳自然补上。
- **流量是增量，只加不赋值**（Agent 读 Xray 计数器时带 reset，重启会归零）。单条坏 entry 跳过而不是整份丢弃：丢一个凭证一个周期，好过丢其他所有人的。凭证刚被删时流量仍记在节点账上——丢掉全局总量比记一笔没有归属的更糟。
- **`OnlinePolicy` 每次连接都下发**，因为 Agent 不跨重连保留策略、启动即 idle。这样万一这帧丢了，落到的是「不采集」这一侧。没开启地址记录时（`EnableOnlineTracking` 未调用）根本不下发策略，收到的上报也直接忽略。
- **节点只能为发给它自己的凭证上报地址。** 每条 `OnlineReport` entry 都用 `CredentialOwner(email)` 校验归属，节点对不上就丢弃并计数告警。没有这道检查，一台被拿下的 VPS 就能替任意订阅者编造两百个地址，而这些地址会落进 `user_devices`——运维日后正是把这张表当作「共享账号」的证据来读的。伪造的证据比丢掉这个功能更糟。
- **会话断开立刻 `Forget(nodeID)`**，不等地址自然老化：节点都断了，用户不该还「通过它在线」。
- Agent 时钟错乱（时间戳来自未来或 <= 0）时保留观测但改用面板自己的时钟——观测本身是真的，错的只是时间。
