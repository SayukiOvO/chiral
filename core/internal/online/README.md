# online — 当前在线源地址（内存态）

每轮轮询把各节点上报的源地址装进内存，回答「这个用户此刻从几个地址连着」。**这里什么都不落盘**：耐久记录（这个用户曾经从哪些地址连过）是另一个问题，在 `store/device.go` 的 `user_devices` 表。

## 关键决策

- **计数是跨节点取并集，不是求和**。一台设备同时连东京和法兰克福是一个地址，不是两个。`Replace` 只替换该节点自己那份贡献，其他节点的观测原样保留——否则一个节点的上报会把用户从别处「踢下线」。
- **Xray 数的是不同源地址，不是会话数**（对 Xray 26.3.27 实测）。同一地址上的三条并发连接算一个，回环地址根本不进 Xray 的统计。所以这个数字的口径始终是「地址数」。
- **空上报是一句话，节点沉默不是**。这就是 `OnlineReport` 用绝对快照、明确豁免增量规则的原因：流量计数器归零意味着「Xray 重启了」，而观测集合归零的含义相反——它意味着「没在观测」，绝不能读成「零设备，放行」。上报了空集 = 该节点上确实没人；没上报 = 被 `Prune` / `Forget` 丢掉，并从 `NodesReporting` 里消失。
- **`complete=false` 会把 `Status.Partial` 置真**，此时 `Count` 是下界而不是总数。
- **TTL 要比轮询间隔宽裕**（`main.go` 取 3 倍），否则用户会在两轮之间闪断。`Forget` 相反，节点一断连就立刻清掉它的贡献而不等 TTL——agent 已经不在了，还按它最后的视图算在线是假的。
